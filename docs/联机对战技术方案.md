# 联机对战（好友实时对弈）技术方案

> 目标：点「分享」把链接发给微信好友，好友点开直接进同一局，两人实时轮流落子。
> 现状：**待用户开通云开发后即可实施**（代码架构已预留位置）。

---

## 一、为什么必须是"回合制 + 云数据库"，而不是长连接

棋类、卡牌、扫雷这类游戏有共同特征：**不需要高频同步**（一秒几次就够）。

| 方案 | 成本 | 适用性 |
|---|---|---|
| **微信云开发（CloudBase）** ★推荐 | 免费额度够用，无需买服务器/域名 | 回合制完全够用；与微信号体系天然集成 |
| 自建 WebSocket 服务器 | 要买服务器 + **备案域名**（个人主体麻烦） | 只对实时性要求高的游戏才需要 |
| 第三方实时服务（LeanCloud 等） | 要额外注册配置 | 同上 |

**结论**：用云开发的「云数据库 + 实时监听（watch）」。好友落子后，
数据库变更会**主动推送**到另一台设备，视觉上就是"实时"。

> 顺带说明：即时对战（FPS、MOBA）才必须长连接；围棋象棋这种**你想 30 秒**也完全没问题。

## 二、整体架构

```
           微信小游戏客户端 A（房主）
                    │  ① 创建房间
                    ▼
        ┌───────────────────────────┐
        │  云开发 · 云数据库          │
        │  collection: rooms         │
        │  { _id, code, game,        │
        │    players:[openidA, ...], │
        │    state, turnOpenid,      │
        │    moves:[...], seq, over }│
        └───────────────────────────┘
              ▲              │
   ③ 落子写回 │              │ ② watch 实时推送
              │              ▼
      客户端 B（好友，点分享链接进入）
```

### 房间的数据结构（示意）

```js
{
  _id: 'r_xxxxx',
  code: 'A7K9Q2',            // 6 位房间码，分享链接里带的就是它
  gameId: 'gomoku',          // 玩哪一款
  difficulty: 'lv2',         // 人机模式用不到；联机时忽略
  players: [openidA, ''],    // 空位表示等人
  seed: 123456,              // 随机种子（棋类可不用）
  state: { /* 棋盘快照，由游戏模块序列化 */ },
  turnOpenid: openidA,
  seq: 12,                   // 步数序号，用于防重放/乱序
  status: 'waiting' | 'playing' | 'over',
  winnerOpenid: '',
  updatedAt: 1790500000000,
}
```

### 三个云函数（或一个带 action 的函数）

| 动作 | 作用 |
|---|---|
| `createRoom(gameId)` | 建房：生成 6 位房间码、写入自己的 openid、返回 code |
| `joinRoom(code)` | 入房：校验未满、占第二个位置；房主收到 watch 推送后开局 |
| `move(code, moveData, seq)` | 落子：校验轮到谁 + seq 连续 → 更新 state 与 turnOpenid |

> **关键**：落子的合法性（轮次、坐标、规则）**必须在云函数里再校验一次**，
> 不能只信客户端，否则容易被改包作弊。

## 三、分享与进入（微信提供的两条能力）

**分享**（游戏内点「邀请好友」按钮）：
```js
wx.shareAppMessage({
  title: '来跟我下一局五子棋',
  query: 'room=A7K9Q2',          // ← 房间码随链接走
});
```

**进入**（好友点开链接启动小游戏）：
```js
const launch = wx.getLaunchOptionsSync();
const code = launch.query?.room;   // 有值 = 从分享链接进来
if (code) joinRoom(code);          // 否则进普通大厅
```

这两个 API 小游戏原生支持，**不需要额外权限**。

## 四、需要改造的地方（估算）

| 模块 | 改动 | 说明 |
|---|---|---|
| 新增 `src/net/room.js` | 房间客户端：create/join/move/watch 封装 | 约 200 行 |
| 新增 `cloudfunctions/` | 3 个云函数（建房/入房/落子） | 约 200 行 |
| `src/app.js` | 大厅加「联机对战」入口；对局中切换"本地/联机"两种驱动 | 约 150 行 |
| 各游戏模块 | 提供 `serialize()/deserialize()` 与 `replay(moves)` | 每个约 30 行 |
| 结算弹窗 | 联机时按钮改为「再来一局 / 退出房间」 | 小改 |

**关键设计**：让游戏模块保持**纯函数**（已有架构天然支持）——
联机只替换"谁触发落子"，规则判定与渲染完全复用。这是当前
`createSession` 架构的最大红利。

## 五、你需要先做的事（3 步，约 15 分钟）

1. **确认小游戏已注册**（你已完成，AppID `wx923e535ada17f5db`）
2. 微信公众平台 → 你的小游戏 → 左侧「**云开发**」→ **开通**
   - 个人主体可用，有免费额度（初创项目基本用不完）
   - 记下 **环境 ID**（形如 `cloud1-xxxxxx`）
3. 告诉我环境 ID，我把 `wx.cloud.init()` 与云函数部署脚本接进来

> ⚠️ **测试号不支持云开发**。你现在用的是正式 AppID，所以没问题。

## 六、实施顺序（开通后）

```
① 接入 wx.cloud.init（初始化）
② 写 3 个云函数并部署（用开发者工具右键上传即可）
③ 客户端房间模块 src/net/room.js
④ 大厅加「联机对战」入口 + 分享按钮
⑤ 用两个设备（或工具+真机）实测：建房 → 分享 → 加入 → 对弈 → 结算
⑥ 断线重连与超时（一方长时间不动可用 watch 提示）
```

**建议先只做「五子棋」的联机**（规则最简单、棋盘状态最小），
跑通链路后再套用到象棋/围棋/扫雷等（架构一致，逐个开）。

## 七、附：为什么不做"实时对战服务器"

- 需要公网服务器（每月几十元起）+ **已备案域名**（个人备案要 10–30 工作日）
- 需要处理连接保活、心跳、重连、扩容
- 收益：只有"毫秒级同步"的游戏才需要，本项目**全是回合制**，用不上

**云开发是明显更省事的路**：不买服务器、不备案域名、与微信登录天然打通。
